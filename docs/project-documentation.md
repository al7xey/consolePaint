# Документация проекта Console Paint

## 1. Назначение проекта

Console Paint - консольное приложение на C++17 для создания и редактирования ASCII-рисунков. Пользователь работает с символьным холстом через текстовые команды: создает поле, выбирает символ кисти, рисует точки, линии и прямоугольники, выполняет заливку областей, очищает холст, сохраняет и загружает результат из текстового файла.

Проект сделан как учебная, но законченная система: он демонстрирует модульную архитектуру, разбор пользовательских команд, работу с двумерной структурой данных, алгоритмы рисования и автоматическое тестирование.

## 2. Цели и границы

### Цели

- Реализовать простое консольное средство для ASCII-графики.
- Поддержать базовые операции рисования и редактирования холста.
- Разделить код на независимые модули, которые можно тестировать отдельно.
- Показать применение паттернов `Command`, `Factory Method`, `Strategy` и `Facade`.
- Обеспечить сохранение и загрузку рисунков в текстовом формате.
- Настроить сборку через CMake и автоматические проверки через CTest.

### Ограничения

- Приложение работает в терминале и не имеет графического интерфейса.
- Изображение хранится как набор строк, а не как растровая графика.
- Поддерживаются базовые примитивы: точка, линия, прямоугольник и заливка.
- Формат файлов - обычный текст без метаданных.
- Отображение нестандартных символов зависит от терминала, кодировки и шрифта.

## 4. Возможности пользователя

| Команда | Назначение |
| --- | --- |
| `CANVAS width height` | Создать новый пустой холст указанного размера |
| `BRUSH symbol` | Изменить текущий символ кисти |
| `POINT x y [symbol]` | Нарисовать точку; если символ не указан, используется текущая кисть |
| `LINE x1 y1 x2 y2 [symbol]` | Нарисовать линию между двумя точками |
| `RECT x1 y1 x2 y2 [symbol]` | Нарисовать прямоугольник по двум противоположным углам |
| `FILL x y [symbol]` | Залить связную область от указанной точки |
| `CLEAR` | Очистить текущий холст |
| `SHOW` | Показать текущее состояние холста |
| `SAVE file` | Сохранить холст в текстовый файл |
| `LOAD file` | Загрузить холст из текстового файла |
| `HELP` | Показать краткую справку |
| `EXIT` | Завершить работу приложения |

Координаты начинаются с `0`: ось `x` направлена слева направо, ось `y` - сверху вниз. Имена команд не зависят от регистра.

## 6. Архитектура

Проект разделен на библиотечную часть `console_paint_lib` и исполняемый файл `console_paint`. Это позволяет использовать одну и ту же бизнес-логику в приложении, unit-тестах и сценарных тестах.

```text
console_paint
+-- PaintApplication
    +-- ConsoleUI
    +-- CommandParser
    +-- CommandFactory
    +-- PaintContext
        +-- Canvas
        +-- ShapeDrawer
        |   +-- BresenhamLineStrategy
        +-- QueueFillStrategy
        +-- FileManager
```

### Основные модули

| Модуль | Ответственность |
| --- | --- |
| `Canvas` | Размеры холста, хранение строк, установка и чтение символов, проверка границ |
| `PaintContext` | Общее состояние приложения: холст, кисть, статус работы, последнее сообщение |
| `ConsoleUI` | Ввод, вывод, приветствие, отображение холста и сообщений |
| `CommandParser` | Разбор строки на имя команды и аргументы |
| `CommandFactory` | Проверка аргументов и создание объекта команды |
| `ICommand` и команды | Единый интерфейс выполнения пользовательских действий |
| `ShapeDrawer` | Рисование точек, линий и прямоугольников |
| `BresenhamLineStrategy` | Алгоритм построения линии Брезенхэма |
| `QueueFillStrategy` | Заливка области через очередь и обход соседних клеток |
| `FileManager` | Сохранение и загрузка холста из текстовых файлов |
| `PaintApplication` | Главный цикл приложения и координация UI, парсера, фабрики и контекста |

## 7. Паттерны проектирования

### Command

Каждое действие пользователя оформлено отдельным классом команды, реализующим интерфейс `ICommand`. Это отделяет разбор ввода от выполнения операции и упрощает тестирование команд.

Примеры: `CanvasCommand`, `BrushCommand`, `DrawPointCommand`, `DrawLineCommand`, `FillCommand`, `SaveCommand`, `LoadCommand`, `InvalidCommand`.

### Factory Method

`CommandFactory` принимает `ParsedCommand`, проверяет количество и формат аргументов, а затем возвращает подходящий объект `ICommand`. Неизвестные или некорректные команды преобразуются в `InvalidCommand` с диагностическим сообщением.

### Strategy

Алгоритмы рисования вынесены в отдельные классы. Линии строятся через `BresenhamLineStrategy`, а заливка реализована в `QueueFillStrategy`. Такой подход позволяет заменить алгоритм без изменения пользовательских команд.

### Facade

`PaintContext` выступает фасадом над внутренними объектами: команды не управляют напрямую `Canvas`, `ShapeDrawer`, `QueueFillStrategy` и `FileManager`, а вызывают методы контекста. Это уменьшает связанность и централизует проверку состояния.

## 8. Алгоритмы

### Рисование линии

Линия строится алгоритмом Брезенхэма. Он работает с целочисленными координатами, не требует вещественных вычислений и подходит для символьной сетки. Метод последовательно выбирает ближайшую клетку холста от начальной точки до конечной.

### Рисование прямоугольника

Прямоугольник строится как четыре линии между углами. Координаты обоих углов предварительно проверяются в `PaintContext`; фактическая отрисовка делегируется `ShapeDrawer`.

### Заливка области

`QueueFillStrategy` использует обход в ширину. Алгоритм запоминает исходный символ стартовой клетки, помещает клетку в очередь, заменяет ее на новый символ и добавляет четырех соседей. Обход продолжается, пока очередь не станет пустой. Если стартовая клетка уже содержит целевой символ, заливка не выполняется.

## 10. Сборка и запуск

### Windows PowerShell

```powershell
cmake -S . -B build
cmake --build build --config Debug --parallel
.\build\Debug\console_paint.exe
```

Запуск с командами без интерактивного ввода:

```powershell
.\build\Debug\console_paint.exe --command "CANVAS 8 4" --command "POINT 2 1 #" --command "SHOW" --command "EXIT"
```

Запуск команд из файла:

```powershell
.\build\Debug\console_paint.exe --script commands.txt
```

### Linux/macOS

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
./build/console_paint
```

### Docker

```bash
docker build -t console-paint .
docker run --rm -it console-paint
```

## 11. Тестирование

Тесты подключаются через CMake и запускаются через CTest. В текущей версии проекта используется Catch2 3.5.4: если библиотека не найдена в системе, она загружается через `FetchContent`.

```powershell
cmake -S . -B build
cmake --build build --config Debug --parallel
ctest --test-dir build -C Debug --output-on-failure
```

### Unit-тесты

| Файл | Что проверяет |
| --- | --- |
| `CanvasTests.cpp` | Работа с пикселями, границами, очисткой, изменением размера и загрузкой строк |
| `CommandParserTests.cpp` | Разбор команд, пробелы, регистр и пустой ввод |
| `CommandFactoryTests.cpp` | Создание команд и сообщения об ошибках |
| `ShapeDrawerTests.cpp` | Точка, линия и прямоугольник |
| `FillStrategyTests.cpp` | Заливка области и старт вне холста |
| `FileManagerTests.cpp` | Сохранение, загрузка и ошибка при отсутствии файла |
| `CommandExecutionTests.cpp` | Кисть, явный символ, очистка, показ холста, выход и ошибки координат |

### Сценарные тесты

| Сценарий | Назначение |
| --- | --- |
| `ScenarioDrawBasic.cpp` | Проверяет базовое рисование точки, линии и прямоугольника |
| `ScenarioFillClosedArea.cpp` | Проверяет, что заливка не выходит за рамку |
| `ScenarioSaveLoad.cpp` | Проверяет сохранение и загрузку холста |
| `ScenarioInvalidInput.cpp` | Проверяет устойчивость к ошибочным командам и аргументам |

## 12. Пример работы

```text
CANVAS 12 6
BRUSH #
RECT 1 1 10 4
FILL 2 2 @
POINT 0 0 *
SHOW
SAVE art.txt
EXIT
```

Ожидаемый результат - прямоугольная рамка, заполненная символом `@`, с отдельной точкой в левом верхнем углу.
